# Glide Contributor Onboarding Guide

Welcome to the Glide project. This guide explains how to get started, what knowledge is
helpful, and how to contribute effectively.

---

## 1. Project Overview
Glide.api is a retro‑correct graphics API that unifies DOS, Windows 95, DirectDraw,
Glide-era behavior, and early OpenGL semantics into a modern Vulkan backend.

---

## 2. Who Can Contribute?
- Graphics programmers
- Vulkan developers
- Retro PC enthusiasts
- Reverse-engineering hobbyists
- Documentation writers
- Testers

All skill levels are welcome.

---

## 3. Required Knowledge (Depending on Role)

### Retro Graphics Contributors
- VGA / Mode X basics
- DOS memory models
- Palette behavior

### Windows 95 Contributors
- GDI BitBlt semantics
- WinG behavior
- DIB sections

### DirectDraw Contributors
- Surface flipping
- Lock/Unlock rules
- Blitting semantics

### Glide Contributors
- TMU behavior
- Combine modes
- Fog tables
- Fixed-function pipeline

### Vulkan Contributors
- Pipelines
- Command buffers
- Synchronization
- Memory models

---

## 4. How to Get Started
1. Read `/docs/PIPELINE_EVOLUTION.md`
2. Read `/docs/RETRO_BEHAVIOR.md`
3. Join the Discord server
4. Introduce yourself in #welcome
5. Pick an era you want to help with
6. Join the matching documentation channel
7. Ask questions — contributors will help

---

## 5. Contribution Workflow
1. Fork the repository  
2. Create a feature branch  
3. Implement or document your changes  
4. Submit a pull request  
5. Participate in review  
6. Merge when approved  

---

## 6. Community Guidelines
- Be respectful  
- Help newcomers  
- Preserve authenticity  
- Document everything  
- No drama  
- No gatekeeping  
- Retro correctness comes first  

---

## 7. Purpose
This guide helps new contributors understand the project, join the community, and begin contributing effectively.
